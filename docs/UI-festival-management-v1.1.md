# 界面设计：节日管理（v1.1）

> **关联**：[PRD-lunar-birthday-festival-v1.1.md](./PRD-lunar-birthday-festival-v1.1.md)、[UI-lunar-calendar-festival-v1.1.md](./UI-lunar-calendar-festival-v1.1.md)  
> **版本**: 1.2  
> **日期**: 2026-04-06  
> **状态**: Draft  

本文档描述 **「节日管理」** 全屏页及 **「添加 / 编辑自定义节日」** 表单的结构与交互。内容包含 **内置传统节日（固定 7 项）** 与 **用户自定义节日（SwiftData 持久化）**，合并展示与排序规则见 PRD §6.3。

**说明**：本页设计**不区分会员层级**；推送与 Toggle 仅受 **系统通知权限** 与 **通知设置中的总开关** 约束。

---

## 1. 页面定位

| 维度 | 说明 |
|------|------|
| **用户目标** | 浏览**全部**即将到来的节日（内置 + 自定义）；**新增 / 编辑 / 删除**自定义节日；可选管理**每个条目是否参与节日前推送**（方案 B）。 |
| **与首页区别** | 首页只展示**近期 N 条**合并排序结果；本页为**完整列表** + CRUD。 |
| **与通知设置区别** | 「通知设置」管总类开关；本页管**分条目**提醒（方案 B）及自定义数据。 |

**产品可选两种强度**（实现前二选一写死）：

- **A（推荐 MVP）**：以 **展示 + 点行进 R1** 为主；提醒仅依赖通知设置总开关。  
- **B**：每行 **「节日前提醒」Toggle**，与总开关逻辑与；自定义条目有独立 `reminderEnabled` 持久化。

下文线框含 **方案 B** 与 **自定义区块**。

与全应用一致：`DesignSystem.Colors` / `Typography` / `Radius` / `Spacing`；`bgPage`、`bgSurface` + `Radius.card`、`separator`。

| 入口 | 说明 |
|------|------|

## 4. 节日管理页结构（自上而下）

```
ScrollView
├── 说明区（small / tertiary）
├── [方案 B] 节日前推送总说明或总开关
├── 区块「内置节日」— 7 行，只读名称（不可删）
├── 区块「我的节日」— 自定义列表
│   └── 每行：名称、下次日期、Toggle / chevron；左滑删除或行内删除
└── 底部或区块内：「+ 添加自定义节日」Primary 或 Secondary
```

### 4.1 顶部说明

- 内置：农历对应公历每年可能变化；除夕为腊月最后一天。  
- 自定义：按用户所选**每年公历 / 每年农历 / 仅一次**推算（见 §6）。  
- 样式：`Typography.small` + `textTertiary`。

### 4.2 内置节日行

- 与 v1.1 一致：图标、`festival.name.*`、副标题「日期 · 还有 X 天」。  
- **无删除**；可 **Reorder** 否：内置顺序固定按产品表。

### 4.3 自定义节日行

| 元素 | 说明 |
|------|------|
| 左 | `star.fill` 或 `person.fill` 置于 `bgIconSubtle`，与内置区分 |
| 中 | 主行：用户输入的 `name`（`body`）；副行：推算的下次日期 + 倒计时 |
| 右 | 方案 B：`Toggle`；方案 A：`chevron.right` |
| **左滑** | **删除**（确认 Alert）；或行尾 `…` 菜单：编辑、删除 |

**仅一次**且已过期：副标题 `festival.user.past`（「已于 YYYY-MM-DD 过去」）或整行灰显 + 提示删除（与 PRD 二选一）。

### 4.4 添加按钮

- 文案：`festival.user.add`（「添加自定义节日」）。  
- 达上限（如 20 条）：`PrimaryButtonStyle` **禁用** + `caption` 说明。

## 5. 添加 / 编辑自定义节日（Sheet 或子页）

### 5.1 字段

| 字段 | 控件 | 校验 |
|------|------|------|
| 名称 | `TextField` + `StandardTextFieldStyle` | 非空，建议上限 20 字 |
| 重复方式 | `Picker` / Segmented：`每年公历` / `每年农历` / `仅一次` | 必选 |
| 每年公历 | 月、日两个 `Picker` 或 `DatePicker`（仅月日） | 合法月日 |
| 每年农历 | 与添加联系人农历一致：月 + 日 | 无闰月首版 |
| 仅一次 | `DatePicker`（`displayedComponents: .date`） | 可选限制：不早于今天（或允许过去仅作备忘，产品定） |
| 节日前提醒 | `Toggle`（若方案 B 且总通知开） | 默认开 |

导航：标题「添加自定义节日」/「编辑」；**保存** `PrimaryButtonStyle`，**删除**（仅编辑模式）`destructive` 或 `Secondary`。

### 5.2 与 R1 的衔接

- 自定义条目点按 → **同一套节日关系 R1**，传入 `userFestivalID`；问候名单逻辑与内置一致。

---

## 6. 交互小结

| 操作 | 结果 |
|------|------|
| 打开节日管理 | 合并刷新内置 + 自定义的「下一次 occurrence」 |
| 添加自定义 | 进入 §5 表单，保存后插入 `UserFestival` |
| 删除自定义 | Alert 确认后 `modelContext.delete` |
| 点任一行 | Present **R1**（内置 id 或自定义 id） |
