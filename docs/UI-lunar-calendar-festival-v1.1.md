本文档描述**界面结构、布局层级、视觉令牌与状态**，供设计与研发对齐；实现须遵守 `DesignSystem` 与 `Localizable.xcstrings`，禁止在视图内硬编码颜色、字号、圆角与间距数值。

**传统节日 / 首页 / 节日管理**：**不区分会员层级**（与 [UI-festival-management-v1.1.md](./UI-festival-management-v1.1.md) 一致）。

## 1. 设计原则与令牌

| 维度 | 要求 |
|------|------|
| 颜色 | 仅 `DesignSystem.Colors.*` |
| 字体 | 仅 `DesignSystem.Typography.*` |
| 圆角 | 表单内嵌块 `Radius.input`；列表/节日卡片 `Radius.smallCard`；大区块 `Radius.card` |
| 页面背景 | `Colors.bgPage` |
| 卡片/输入容器 | `Colors.bgSurface`，描边 `Colors.border` 1pt |
| 区块标题 | `Typography.title3` + `textPrimary` |
| 字段标签 | `Typography.caption` + `textSecondary` |
| 辅助说明 | `Typography.small` + `textTertiary` |
| 水平页边距 | `Spacing.pageHorizontal`（16） |
| 表单大区块间距 | 与现「添加联系人」一致：`VStack(spacing: 24)`（外层）/ 字段组 `spacing: 20` |

**暗色模式**：不单独写死颜色，依赖令牌自动适配。

## 3. 添加/编辑联系人：生日区域

### 3.1 信息架构

将原「单一生日开关 + DatePicker」拆为**两条独立记录**，与 PRD「可同时设置公历与农历」一致：

1. **公历生日**（可选）  
2. **农历生日**（可选）  

二者互不排斥；至少一项有值时视为「已填写生日」（具体校验与保存逻辑见需求文档）。

### 3.2 布局结构（自上而下）

```
[VStack spacing: 24 — 与现 formSection 一致]
  … 姓名、关系 …

  [生日 — 分组语义]
    Caption: 「生日」— Typography.caption, textSecondary
    [VStack spacing: 12~16]
      ┌─ 公历生日行 ─────────────────────────┐
      │ [Caption: 公历生日]                    │
      │ 圆角容器 Radius.input, bgSurface, border │
      │   HStack: DatePicker 或占位 | Spacer | 开关/日历 │
      └────────────────────────────────────────┘
      ┌─ 农历生日行 ─────────────────────────┐
      │ [Caption: 农历生日]                    │
      │ 圆角容器同上                           │
      │   HStack: 摘要「八月十五」或占位 | 开关   │
      │   [若开启] HStack: 月 Picker | 日 Picker   │
      └────────────────────────────────────────┘

  … 手机、地址、备注 …
```

### 3.3 公历行

- **未开启**：容器内左侧为占位文案（本地化 key，禁止硬编码 `mm/dd/yyyy`）；右侧为日历图标按钮或 Toggle，行为与现版「点击启用生日」一致。  
- **已开启**：`DatePicker`，`displayedComponents: .date`，`tint` 使用 `Colors.primary`。  
- 容器内边距：与现 `birthdayField` 一致（约 vertical 12 / horizontal 16）。

### 3.4 农历行

- **未开启**：占位 + 开关；占位说明可为「未设置」类 tertiary 文案。  
- **已开启**：  
  - **月份**：`Picker`，选项为正月～腊月（全部走本地化字符串表，禁止代码写死中文）。  
  - **日期**：`Picker` 初一～三十；当某农历月无「三十」时，选项中不包含三十或自动回落到廿九（与历法一致）。  
- **布局**：月、日两个选择器建议同一行 `HStack`，`frame(maxWidth: .infinity)` 均分；若 wheel 高度过大，可改为 `Menu` + 当前选中摘要，点击后分步选择（产品可选一种，全 App 统一）。

### 3.5 错误与禁用

- 农历开启但月日未选全：**保存**沿用现有主按钮位置；可禁用主按钮或弹出与现版一致的校验 Alert（独立 message key）。  
- 图标尺寸：使用 `Typography` 档位映射的图标字体（如 `body` / `title3`），**禁止** `.font(.system(size: 18))` 硬编码。

### 3.6 建议本地化 key（示例）

| Key | 用途 |
|-----|------|
| `contact.add.birthdaySection` | 区块总标题「生日」 |
| `contact.add.birthday.gregorian` | 公历生日标签 |
| `contact.add.birthday.lunar` | 农历生日标签 |
| `contact.add.birthday.placeholder` | 未选日期的占位 |
| `contact.add.lunar.month.*` | 正月…腊月（或单 key + 参数，依工程约定） |
| `contact.add.lunar.day.*` | 初一…三十 |

## 4. 联系人详情：个人信息

### 4.1 布局

在「个人信息」标题（`title3`）下方、`bgSurface` + `Radius.smallCard` 的列表内：

| 顺序（建议） | 行内容 | 图标（SF Symbol） |
|--------------|--------|-------------------|
| 1 | 公历生日（有则显示） | `birthday.cake.fill` |
| 2 | 农历生日（有则显示） | `moon.stars.fill`（或与蛋糕区分即可） |
| 3 | 圈层 | 保持现有 |
| … | 电话、备注 | 保持现有 |

**仅公历**：只显示公历行。  
**仅农历**：只显示农历行。  
**两者皆有**：两行均显示；标签区分「公历生日」「农历生日」，值分别为格式化公历日期与「农历八月十五」全文。

### 4.2 行样式

复用现有 `infoRow`：`HStack` 左图标 24×24、`caption` 标签、`Spacer()`、右侧值 `caption` + `textPrimary`，行高与 Divider 缩进（`leading 52`）与现版一致。

### 4.3 建议本地化 key

| Key | 用途 |
|-----|------|
| `contact.detail.birthday.gregorian` | 公历生日 |
| `contact.detail.birthday.lunar` | 农历生日 |

## 5. 首页：传统节日区块

### 5.1 位置

插入在 **年度总览卡片（summarySection）之后**、**临近事件（upcomingSection）之前**，避免与用户自建事件的轮播混淆。

整体仍属 `ScrollView` 内 `VStack(spacing: 20)`。

### 5.2 区块标题

- 左侧：`Typography.title3` + `textPrimary`，文案 key：`home.festival.sectionTitle`（示例：「传统节日」）。  
- 右侧：可选 `caption` + `Colors.primary` 的「查看全部」，`NavigationLink` 至 **节日管理** 全屏页（与 `sectionHeader` 中 `common.viewAll` 行为一致）；见 [UI-festival-management-v1.1.md](./UI-festival-management-v1.1.md)。

### 5.3 节日卡片（单条）

**尺寸建议**：宽度通栏（减 `pageHorizontal`）；高度约 **72～88 pt**（低于临近事件轮播 196pt，避免抢视觉）。

**结构**：

```
HStack(spacing: 12)
  [左] ZStack: 图标 24pt, primary 色, 置于 40×40 圆角矩形容器 bgIconSubtle, Radius.input
  [中] VStack(alignment: .leading, spacing: 4)
         节日名 — title3 或 body semibold, textPrimary
         副标题 — caption, textSecondary（「中秋节 · 还有 12 天」用 String(format:)）
  [右] chevron.right, caption 档, textTertiary
```

**容器**：`bgSurface`、`Radius.smallCard`、内边距约 14～16、细描边与首页空状态卡一致（`primary.opacity(0.05)`）。

**点击**：整卡点按 → 打开 **节日关系（R1）** Sheet（`festivalId`）；不区分会员。

### 5.4 展示条数与「查看全部」

| 规则 | 说明 |
|------|------|
| 首页列表 | 将 **内置节日** 与 **用户自定义节日**（`UserFestival`，见 PRD §6.3）按「下一次公历 occurrence」**合并排序**，取**即将到来的**前 **N 条**（建议 3～5）；仅内置时行为与原先一致。 |
| 查看全部 | 区块标题右侧「查看全部」→ **节日管理**页，展示内置 7 项 + 全部自定义条目，支持 CRUD；详见 [UI-festival-management-v1.1.md](./UI-festival-management-v1.1.md)。 |

### 5.5 空状态

若内置节日列表在当年计算异常（不应常见），可隐藏整段；正常情况**不应**出现「无节日」空状态。

### 5.6 建议本地化 key

| Key | 用途 |
|-----|------|
| `home.festival.sectionTitle` | 区块标题 |
| `home.festival.daysLeftFormat` | 「%@ · 还有 %d 天」 |
| `common.viewAll` | 查看全部（与首页其它区块一致，链到节日管理） |
| `festival.name.*` | 春节、元宵…除夕（与内置 id 对应） |

## 6. 通知设置

### 6.1 生日提醒行

保持现有 **一行 Toggle** + 图标 `birthday.cake.fill` + 标题 `settings.notification.birthday`。

**可选增强**：在该行下方增加一行 **说明**（非独立 Toggle），`small` + `textTertiary`，左缩进与文字对齐（与「通知已关闭」灰色说明一致），key：`settings.notification.birthday.hint` —— 说明涵盖**公历与农历生日**（若产品将二者绑在同一开关）。

### 6.2 节日提醒（若产品独立开关）

- 位置：插在「生日」与「下一项」之间，`Divider` + `padding(.leading, 56)` 与现列表一致。  
- 图标：建议 `sparkles` 或 `moon.stars`。  
- 标题：`settings.notification.festival`。  
- 通知总关或系统未授权时：Toggle **禁用**，与现有「通知类型」区行为一致（不引导付费）。

---

## 7. 交互与动效

- 公历/农历开关切换：使用 `withAnimation(.easeInOut(duration: 0.15))` 与现 `birthdayField` 一致。  
- 节日卡片点击 → Sheet 打开 **节日关系（R1）**，**不**在子页面再嵌套 `NavigationStack`（沿用根 `HomeView` 的 `sheet` 模式）。

---

## 8. 无障碍

- 公历/农历开关：`accessibilityLabel` 区分二者。  
- 节日卡片：`accessibilityElement(children: .combine)`，读出「中秋节，还有 12 天，按钮」。  
- 「查看全部」：读出「查看全部节日，按钮」。
