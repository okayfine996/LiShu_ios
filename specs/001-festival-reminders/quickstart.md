# Quickstart: Traditional Festival Reminders

## Goal

验证“传统节日提醒”功能在首页展示、通知调度和快速创建事件三个维度均符合规格。

## Prerequisites

- 使用 Debug 构建运行应用
- 设备或模拟器允许通知权限
- 当前分支为 `001-festival-reminders`
- 已准备若干测试联系人，其中至少包括：
  - 2 个“家人/亲属”联系人
  - 1 个非“家人/亲属”联系人

## Validation Steps

### 1. 首页节日卡片展示

1. 启动应用并进入首页
2. 确认首页在年度汇总下方显示传统节日卡片区块
3. 确认只显示最近 3 个即将到来的节日
4. 确认卡片按时间先后排序
5. 确认卡片展示节日名称与剩余天数

**Expected Result**:
- 首页显示 3 张节日卡片
- 顺序稳定
- 不会覆盖或破坏现有“即将到来的事件”区块

### 2. 跨年与边界日期

1. 使用测试时间源或调试入口切换到接近农历年末的日期
2. 重新加载首页
3. 检查已过节日是否跳到下一年的下一次发生日期

**Expected Result**:
- 不显示过去日期
- 节日卡片始终对应“下一次将发生”的日期

### 3. 节日提醒通知

1. 打开通知设置
2. 开启总通知和事件提醒
3. 触发通知重排
4. 检查待发送通知队列
5. 模拟节日前 1 天的触发场景

**Expected Result**:
- 每个节日实例只有 1 条汇总通知
- 通知文案包含节日名
- 最多显示 3 个联系人，其余显示“等 X 人”
- 没有命中联系人时，通知正文仍完整可读

### 4. 现有通知开关兼容

1. 保持首页节日卡片可见
2. 关闭总通知开关
3. 检查通知是否全部取消
4. 再开启总通知但关闭事件提醒

**Expected Result**:
- 首页节日卡片始终可见
- 总通知关闭时不发送节日提醒
- 事件提醒关闭时不发送节日提醒

### 5. 快速创建节日事件

1. 在首页点击任意节日卡片
2. 进入新建事件页
3. 检查名称、类型、日期的预填结果
4. 保存事件
5. 返回首页与事件列表验证结果

**Expected Result**:
- 打开的是现有新建事件流程
- 名称、事件类型、日期已预填
- 用户仍可编辑
- 保存后事件出现在现有事件流中

## Suggested Automated Coverage

- `LiShuTests`
  - 节日下一次发生日期计算
  - 最近 3 个节日排序
  - 联系人筛选与“等 X 人”摘要格式
  - 预填事件上下文映射

- `LiShuUITests`
  - 首页节日卡片显示
  - 点击卡片进入新建事件
  - 通知设置开关对节日提醒的影响

## Regression Checklist

- 现有 `upcomingEvents` 区块未退化
- 现有事件提醒未重复或被覆盖
- 生日提醒和回礼提醒逻辑未受影响
- 首页滚动性能无明显下降
- 所有新增文案都已本地化
